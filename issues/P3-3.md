# P3-3 — The README says twice that fromArray() "binds positionally", while …

## Finding / 问题

- EN: The README says twice that fromArray() "binds positionally", while another README section, the trait’s own docblock and the tests all show PHP 8 named-argument binding (extra or missing keys throw). A reader who takes the first statement will believe column order matters and that a renamed or reordered parameter is harmless.
- 中文: README 两处称 fromArray()「按位置绑定」，而 README 另一节、trait 自己的 docblock 与用例都表明是 PHP 8 命名参数绑定（多键或缺键都会抛错）。采信第一句的读者会以为列顺序重要、而参数改名或调序无害。
- Where / 位置: `README.md:31 and :112 vs README.md:73/:99, src/DataAccess.php:33-35, tests/DataAccessTest.php:48-66`
- Verification / 验证: reproduced / 已实证

The finding holds: `src/DataAccess.php:48` is `return new static(...$row);`, and with a string-keyed row PHP 8.x spreading binds by **name**, not position. Re-reproduced through the module's own `vendor/autoload.php` (PHP 8.5.10), in a temp dir outside the repo, on a probe class with `__construct(int $id, string $user_name)`: the row `['user_name' => 'Alice', 'id' => 7]` — keys in the reverse of the parameter order — constructs fine (`{"id":7,"user_name":"Alice"}`), which positional binding could not do, while a renamed key throws loudly (`Error: Unknown named parameter $identifier`). So the two "positionally" lines contradicted `README.md:73`, `README.md:99` and the code; a positional (list) row does bind positionally, but that is not the documented path — `README.md:73` requires keys to match the parameter names. Level kept at **P3**, not raised to P1: the rubric's P1 is documentation that fails when copied or states the opposite of the code, and here nothing a reader could copy misbehaves — the misleading word is in explanatory prose about "no hydration/casting", and the renamed-parameter case it invites fails loudly with a native `\Error` rather than silently. Fix: `README.md:31` → "binds by parameter name only", `README.md:112` → "only binds the row by parameter name (no hydration, no casting)"; the Chinese twins at `README.md:417` ("只按参数名绑定") and `README.md:496` ("仅按参数名绑定") reworded to match. `grep -nE 'positionally|按位绑定' README.md` now returns nothing, and all four lines agree with `README.md:73/:99`. No PHPUnit test is added: the defect is prose with no code seam, the same disposition as P3-1 and P3-2 in this module; the check that replaces it is the grep parity above. No code changed.
